Two remote-code-execution flaws are being exploited in the wild, one of them now in CISA's KEV catalog; a ten-year-old NGINX HTTP/2 overflow gets fixes; a Java decoder bug is real but gated on specific silicon; and third-party scripts, a hijacked PyPI package and an unexplained federal network outage fill out the day.

Actively exploited

CISA added Perforce Puppet Enterprise's deserialization flaw, CVE-2026-115731, to the KEV catalog citing reports of active exploitation. NVD scores it 9.4 Critical under CVSS 4.0, and the mechanics matter more than the number: any client holding a CA-signed agent certificate can execute code on the Puppet Server as its service user by submitting a crafted rich-data report over PUT. Where the certificate authority autosigns requests without strong verification, an unauthenticated network attacker can first obtain such a certificate — so exposure depends on CA configuration, not just patching cadence. Supplied vulnerable ranges cover Puppet 8.0.0 up to 8.22.2 and 9.0.0 up to 9.1.3, and Puppet Enterprise 2023.8.0 up to 2023.8.13, 2025.0.0 up to 2025.12.1, plus 2026.0.0. CISA's required action is to apply mitigations per vendor instructions under its risk-based patching directive, with a federal remediation due date attached; ransomware use is listed as unknown, so treat that as an open question rather than a clean bill. Hackers Exploiting Critical Puppet RCE Flaw Affecting Enterprise Management Servers

Apache has confirmed in-the-wild exploitation of CVE-2026-129448, a 9.8 Critical unauthenticated deserialization in Roller's XML-RPC endpoint that reaches code execution because vendor extension types are deserialized before the requester is authenticated. Affected versions are 4.0.0 through 6.1.4; the record notes this is the same vulnerability as CVE-2026-82384, which had listed only 6.1.5 as affected — a scoping correction worth flagging to anyone who triaged off the earlier ID. Upgrade to 6.1.6 or later is the real fix; interim workarounds are setting enabledForExtensions to false or removing the /roller-services/xmlrpc servlet mapping and restarting. Disabling XML-RPC in the admin UI is explicitly not sufficient, because older versions deserialize before that check. Critical Apache Roller RCE Flaw Under Active Exploitation, No Authentication Required The KEV catalog returns a confirmed miss for this CVE, which — as ever — says nothing about exploitation and everything about catalog timing.

Vulnerabilities

NGINX's "nginx2root" bug, CVE-2026-123007, is the day's most uncomfortable read: a heap buffer overflow in HTTP/2 processing where the flow-control window can exceed its threshold, present since 1.9.5 and fixed in 1.31.9 and 1.30.7. CVSS 4.0 puts it at 9.2 Critical, network-reachable with no privileges or interaction, but with high attack complexity — the reliable outcomes are worker crashes and memory corruption, with code execution contingent on ASLR being disabled or bypassable. It is data-plane only, with no control plane exposure, and there is no KEV listing. Internet-facing HTTP/2 terminators are the population that matters here. 10-Year-Old NGINX HTTP/2 Flaw Lets Unauthenticated Attackers Execute Code on Servers

CVE-2026-114938, marketed as Java4Shell, is a High-severity (8.1 CVSS 3.1) out-of-bounds write in HotSpot's Base64 handling, reported by researchers to affect Java 17.0.6 and later, with the vulnerable path running only on x86-64 chips supporting AVX-512 VBMI. Oracle's affected-version list spans specific builds across Java SE 8, 17, 21, 25 and 27 plus GraalVM editions. The disclosure names Jira, Jenkins, Keycloak and three other applications as reachable targets. Analysis: the combination of high attack complexity, a hardware feature gate and no supplied report of exploitation makes this a patch-queue item rather than an emergency — but the hardware prerequisite is a poor filter, since AVX-512-capable servers are exactly the ones running build and identity infrastructure. No KEV listing is supplied. Java4Shell Flaw (CVE-2026-114938) Enables Pre-Auth RCE in Jira, Jenkins, Keycloak and More

Breaches

At least 178 top web destinations served malware to visitors over a 24-hour window via a security vulnerability involving Optimizely's customization and testing platform, with named sites including the BBC, CNN, Equifax and Ledger. No CVE or root-cause detail was supplied; what is clear is the shape of the failure — a vendor script trusted across many properties became a delivery channel, and the testing tooling meant to vary experiences varied them toward exploits. Microsoft's agent-framework package on PyPI was compromised to ship versions 1.26.1 and 1.26.2, published 33 minutes apart, designed to run a credential stealer on every Python start and aimed at Azure, Azure DevOps and GitHub Actions secrets. Eight separate research teams are credited with the reporting, which suggests independent confirmation rather than a single vendor claim. Any build agent that installed during that window should be assumed to have leaked its cloud and CI credentials.
