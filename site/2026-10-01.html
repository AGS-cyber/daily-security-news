All three CVEs in today's selection are KEV-listed and reported as exploited: a Critical Cisco Catalyst SD-WAN Manager authentication bypass, a High-severity Zimbra command injection hit before disclosure, and an Apple CoreGraphics memory-corruption bug that now has a public proof-of-concept. Below them sit breach confirmations from the Pentagon, Bitget and DIVD, a ransomware takedown with an alleged teenage administrator, and fresh numbers on GitHub secret sprawl.

Actively exploited

CISA added CVE-2026-76504 to KEV after reports of active exploitation, and it is the day's most urgent item CISA Adds Exploited Cisco Catalyst SD-WAN Manager Auth Bypass to KEV. NVD rates it 9.8 Critical and describes improper URI-encoding handling in an HTTP request that defeats an authentication rule guarding a specific API endpoint; a crafted request reaches that API with admin privileges, over the network, with no credentials and no user interaction. Affected Catalyst SD-WAN Manager ranges are those below 20.9.10.1, below 20.12.8.2, below 20.15.6.1, below 20.18.4.1, below 26.1.2.1, and 26.2 itself. The KEV entry directs federal agencies to apply mitigations under BOD 26-04 on a deadline three days after the catalog addition, and records ransomware campaign use as unknown.

The Zimbra flaw is the reminder that "exploited" and "trivially exploitable" are different claims Zimbra Vulnerability Exploited in the Wild Prior to Public Disclosure. CVE-2026-73570 is KEV-listed at 8.9 High — not Critical — a CWE-78 OS command injection that requires the optional zimbra-snmp package to be installed and SNMP notifications enabled, and is fixed in versions from 10.1.20. An unauthenticated attacker sending specially crafted requests can execute operating-system commands as the Zimbra user, and the supplied reporting says exploitation began before public disclosure and can occur via crafted email without user interaction; the CVSS vector's high attack complexity and changed scope reflect that this is not a one-size-fits-all mail-server takeover. Analysis: the practical question for defenders is whether the SNMP component is present, since servers that do not match that prerequisite do not satisfy the described conditions.

Apple's CVE-2026-86950 is an out-of-bounds write now KEV-listed at 8.8 High, with a first public proof-of-concept in circulation Apple CoreGraphics PoC Emerges as WhatsApp PDF Checks Hint at Possible Delivery Path. The trigger is a PDF carrying a crafted embedded font that crashes unpatched iPhones and Macs; the released code produces a crash rather than code execution, and the excerpt cuts off before resolving whether that crash can be turned into a working exploit. Apple has said the issue may have been used in an extremely sophisticated attack against specific targeted individuals on iOS before version 27, and fixes ship in iOS and iPadOS 26.7.1, macOS Sequoia 15.8.1 and macOS Tahoe 26.7.1. The delivery path hinted at in the headline is a hint, not a supplied finding. Analysis: a crash-only PoC with a user-interaction prerequisite keeps near-term risk targeted rather than mass, but it raises the incentive to weaponise a bug that is confirmed as exploited.

Breaches

The Pentagon's Defense Manpower Data Center is notifying millions of service members that hackers stole their data following a breach of the department's human resources management system; the headline puts the figure above three million people Hackers stole Pentagon personnel records of over 3 million people. No CVE, root cause or actor is supplied, so the significance here is scale and confirmation rather than mechanism.

Bitget has confirmed that attackers stole $387.5 million, attributing the intrusion to a zero-day in third-party security products on the basis of investigation findings it cites from SlowMist, and says a customised attacker tool was recovered Bitget Confirms Third-Party Zero-Day Behind $387.5 Million Cryptocurrency Theft. No CVE identifier or named actor appears in the supplied text, and the excerpt is truncated mid-account. Analysis: if a third-party security product really was the entry point, this is exchange supply-chain risk again — but that reading rests on an investigation summary we only see in part.

DIVD says its own network was breached through a chain of two zero-days in the open-source Zammad ticketing system DIVD says Zammad zero-days enabled AI-driven network breach. No CVE IDs are supplied for either flaw, and the "AI-driven" framing in the headline is not substantiated by the truncated excerpt. Analysis: two undisclosed flaws in a ticketing system used for vulnerability handling would be notable for anyone running similar infrastructure, but chain details, the AI claim and impact remain unverified on this evidence.
