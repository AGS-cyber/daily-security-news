Today's slate is dominated by active exploitation of the systems that build, sign, and ship everyone else's software: a self-hosted GitLab instance, an MSP remote-access console, an artifact repository, and two developer-facing services. Add a breach caused by a forged emergency data request and a hardware result that dents confidential computing's central promise, and the day's common thread is that attackers are going after the trusted plumbing rather than the applications running on top of it.

Actively exploited

The lead is CISA: Hackers now exploit max severity GitLab flaw in attacks, where CISA has confirmed that a maximum-severity GitLab flaw is being exploited. Treat that as the day's most actionable item. A self-hosted GitLab server is not just version control — it holds CI runners, repository deploy keys, package registries, and, in most organisations, a dense concentration of tokens that other systems trust implicitly. A maximum-severity flaw in that position converts a single internet-facing instance into a credential-harvesting platform, and the correct posture is to assume secrets in the affected instance were exposed even if the logs look clean. Anyone running self-hosted GitLab should have this as a standing change-freeze exception today.

ConnectWise Patches ScreenConnect Vulnerability Exploited in Worm-Like Attacks is the same story aimed at the managed-services tier. ConnectWise has patched a ScreenConnect vulnerability exploited in worm-like fashion, where attackers can send files through an active remote session and execute them without authorisation. The technical detail matters less than the topology: ScreenConnect deployments sit at the centre of an MSP's access to every customer it serves, so a foothold in one technician console is not a single compromise but a distribution mechanism. The phrase "worm-like" is the warning — expect lateral movement to look like normal administrative traffic.

Three JFrog Artifactory Flaws Exploited for Backdoor Deployment raises the stakes from access to integrity. Three JFrog Artifactory flaws have been chained to bypass authentication and elevate to administrator, after which backdoors were deployed. An artifact repository is the trust anchor of a build pipeline: if you can write to it, you can substitute what everyone downstream compiles, signs, and ships. That reframes incident response. The question is no longer only what the attackers took out of the repository, but what they put into it — and whether any published artifact was tampered with during the window of exposure.

Two developer-infrastructure stories point at the same soft target from different directions. Hackers target exposed Vite dev servers to steal AWS, Azure secrets describes a mass-scanning campaign against internet-exposed Vite development servers, harvesting AWS and Azure credentials and configuration data. The finding is not that Vite is broken; it is that development servers are routinely run on public addresses with live cloud keys, and that a dev server with cloud credentials is a production compromise with a staging label. Red Heron Exploits Gitea RCE to Compromise 13 Organizations Across Six Countries shows what a serious actor does with that access: a Chinese threat actor tracked as Red Heron rapidly weaponised a Gitea remote code execution flaw, compromising 13 organisations across six countries after scanning on the order of a thousand internet-facing instances, plus a separate dataset of hundreds of Taiwan-based systems. Rapid weaponisation of freshly disclosed bugs in internet-facing development infrastructure is now a reliable pattern rather than an outlier.

Chinese Hackers Exploit Critical Tencent Software Flaw for One-Click Code Execution widens the aperture beyond servers. A critical flaw in a widely installed Chinese-language Tencent input method editor for Windows allows one-click remote code execution, and it is already being exploited. Input method editors deserve more respect than they get: they sit inside the process context of whatever the user is typing into, so exploitation requires no exposed service and no user misconfiguration — just a victim who types. It is also a reminder that desktop software with a vast install base and an uneven update cadence is an attack surface that server-centric threat models routinely miss.

Breaches

The day's most instructive breach is Revolut handed customer data to fraudsters using government email account. Revolut has confirmed it disclosed sensitive customer data — including passports and financial details — to fraudsters who submitted emergency data requests from a legitimate government email account. Emergency disclosure channels exist because genuine life-safety situations cannot wait for normal legal process, which means they are, by design, the path of least verification. The lesson is not that the channel should be abolished but that providers should treat it as a high-risk transaction class: corroborate the requester through an out-of-band channel, scope the response to the stated emergency, log and review it, and accept that a plausible sending domain proves nothing.

Research

Finally, New DDRop Attack Breaks Intel TDX and AMD SEV-SNP Confidential Computing is worth an hour of reading even though it demands a powerful attacker. The DDRop hardware attack silently drops writes to a server's memory so the processor keeps reading stale encrypted data as if it were current, breaking the memory confidentiality guarantee that Intel TDX and AMD SEV-SNP are sold to provide. It requires someone who already controls the server's software and can briefly access the machine to insert a small circuit — so the realistic threat model is a hostile or compromised host operator, or a co-tenant with hands on hardware, not a remote attacker. That is exactly the model confidential computing exists to defeat. If your architecture says "trust the CPU, not the operator," that assumption has just been given a crack, and the mitigation conversation belongs with your hardware vendor rather than in a patch queue.
